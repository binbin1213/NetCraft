# 可观测性增强建议

## 1. 缺失的可观测点

根据测试清单中的可观测性要求，当前代码缺少以下关键日志记录：

### 1.1 服务启动日志
- **缺失点**：服务启动时未记录 SECRET_KEY 设置情况
- **缺失点**：服务启动时未记录 CORS 配置信息

### 1.2 认证日志
- **缺失点**：认证失败时未记录详细错误信息
- **缺失点**：关键操作（如用户注册、登录）未记录日志

## 2. 建议的增强措施

### 2.1 增加服务启动日志

#### 修改文件：`backend/app/main.py`
```python
# 在CORS配置后添加日志
import logging

# 配置日志
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

# Get allowed origins from environment variable, default to localhost for development
ALLOWED_ORIGINS = os.getenv("ALLOWED_ORIGINS", "http://localhost:5173").split(",")

app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# 记录CORS配置
logger.info(f"CORS configuration: ALLOWED_ORIGINS={ALLOWED_ORIGINS}")
```

#### 修改文件：`backend/app/auth.py`
```python
# 配置日志
import logging
logger = logging.getLogger(__name__)

# Configuration
SECRET_KEY = os.getenv("SECRET_KEY")
if not SECRET_KEY:
    logger.error("SECRET_KEY environment variable is not set")
    raise ValueError("SECRET_KEY environment variable is not set")

logger.info("JWT SECRET_KEY loaded successfully from environment variable")
```

### 2.2 增加认证日志

#### 修改文件：`backend/app/main.py`
```python
# 在认证相关路由添加日志
@app.post("/users/", response_model=UserRead)
def create_user(user: UserCreate, session: Session = Depends(get_session)):
    # 检查用户名是否已存在
    existing_user = session.exec(select(User).where(User.username == user.username)).first()
    if existing_user:
        logger.warning(f"User registration failed: username {user.username} already exists")
        raise HTTPException(status_code=400, detail="Username already registered")
    
    # 创建新用户
    hashed_password = get_password_hash(user.password)
    db_user = User(username=user.username, password_hash=hashed_password)
    session.add(db_user)
    session.commit()
    session.refresh(db_user)
    
    logger.info(f"User registered successfully: {user.username}")
    return db_user

@app.post("/token/")
def login_for_access_token(
    form_data: OAuth2PasswordRequestForm = Depends(),
    session: Session = Depends(get_session)
):
    user = session.exec(select(User).where(User.username == form_data.username)).first()
    if not user or not verify_password(form_data.password, user.password_hash):
        logger.warning(f"Login failed for user: {form_data.username}")
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Incorrect username or password",
            headers={"WWW-Authenticate": "Bearer"},
        )
    
    access_token_expires = timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    access_token = create_access_token(
        data={"sub": user.username},
        expires_delta=access_token_expires
    )
    
    logger.info(f"User logged in successfully: {form_data.username}")
    return {"access_token": access_token, "token_type": "bearer"}

# 在get_current_user函数中添加日志
async def get_current_user(token: str = Depends(oauth2_scheme), session: Session = Depends(get_session)):
    credentials_exception = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Could not validate credentials",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str = payload.get("sub")
        if username is None:
            logger.warning("JWT payload missing 'sub' claim")
            raise credentials_exception
    except JWTError as e:
        logger.warning(f"JWT decoding failed: {str(e)}")
        raise credentials_exception
        
    user = session.exec(select(User).where(User.username == username)).first()
    if user is None:
        logger.warning(f"User not found for JWT username: {username}")
        raise credentials_exception
    
    logger.debug(f"User authenticated successfully: {username}")
    return user
```

## 3. 增强后的可观测性收益

1. **服务启动时**：
   - 记录 SECRET_KEY 是否成功加载
   - 记录当前 CORS 配置，便于调试环境问题

2. **认证过程中**：
   - 记录用户注册成功/失败情况
   - 记录用户登录成功/失败情况
   - 记录 JWT 验证失败的详细原因
   - 记录认证成功的用户信息

3. **监控与告警**：
   - 可基于日志监控 JWT 认证成功率
   - 可基于日志监控 CORS 错误率
   - 可基于日志监控服务启动成功率
   - 可及时发现异常登录尝试

## 4. 验收标准

1. **服务启动日志**：
   - 启动服务时，日志中包含 "JWT SECRET_KEY loaded successfully from environment variable" 或 "SECRET_KEY environment variable is not set"
   - 日志中包含 "CORS configuration: ALLOWED_ORIGINS=[...]"

2. **认证日志**：
   - 用户注册成功时，日志中包含 "User registered successfully: [username]"
   - 用户注册失败（用户名已存在）时，日志中包含 "User registration failed: username [username] already exists"
   - 用户登录成功时，日志中包含 "User logged in successfully: [username]"
   - 用户登录失败时，日志中包含 "Login failed for user: [username]"
   - JWT 验证失败时，日志中包含相关错误信息

3. **日志级别**：
   - 错误信息（如 SECECRET_KEY 未设置）使用 ERROR 级别
   - 警告信息（如登录失败）使用 WARNING 级别
   - 信息性日志（如服务启动、注册成功）使用 INFO 级别
   - 调试信息（如认证成功）使用 DEBUG 级别

## 5. 实现复杂度

- **修改范围**：仅涉及 `backend/app/auth.py` 和 `backend/app/main.py` 两个文件
- **修改量**：约 50 行代码
- **风险**：低风险，仅增加日志记录，不影响现有功能
- **测试成本**：可通过查看日志验证，无需额外测试用例
